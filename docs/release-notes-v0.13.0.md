# Life 0.13.0

Life 0.13.0 adds a native Local environment and strengthens conversation recovery, streaming history, provider ownership, and the controls used while work is running.

> Release preparation: final integrated active-recovery verification and publication are pending. This draft does not certify the final release graph.

- **Start on your own machine.** New installations open the Local environment. Browse projects and files, use a real terminal, and run the installed Codex or Claude Code CLI with the local account and configuration. Local stays available beside saved SSH machines, while an explicitly selected SSH environment retains its selection after restart. Local uses a distinct persistent identity so threads, projects, and permission requests stay with their original environment. Native Local execution requires a POSIX shell; Windows continues to support SSH environments.
- **Keep the provider's own conversation.** Life continues to use Codex's app-server protocol and Claude Code's streaming CLI. Submitted text, provider input, session identity, workspace ownership, and native approval responses retain their original meaning. Stopping work and releasing an idle provider wait for the actual provider lifecycle so a cold follow-up can resume the same conversation.
- **Recover large and streaming histories.** Native history loading and checkpointing use owned workers, bounded delivery, and atomic disk commits. Streaming saves send acknowledged changes while keeping the complete recoverable history on disk. Existing histories, opaque records, unknown fields, attachment references, and source order survive loading and recovery. Restored queues stay paused; interrupted or unknown work remains explicit.
- **Stay responsive as conversations grow.** Streaming event batches, history search, message navigation, transcript rendering, sidebar projections, and workspace surfaces reduce repeated work. Native history parsing and serialization move off the interface path. Exact text, native Find, selection, expandable activity, and available raw output remain usable.
- **Keep approvals, Stop, drafts, and Studio recoverable.** Native permission choices retain their provider meaning. Pending requests and running state remain distinct from successful completion. Agents, Research, and Studio retain their own conversation and draft ownership through navigation, reload, checkpointing, and recovery; newer edits are preserved when asynchronous work completes.

The native asynchronous services now use Effect 4.0.0-rc.118 for typed failures, cancellation, concurrency, resource ownership, and application lifecycle management. Electron, SSH callbacks, worker communication, and React keep their existing integration boundaries, and the provider protocols remain native.

## Active restart recovery: final verification pending

The active-recovery candidate records ownership needed to reattach the original provider process and session after renderer reload or a cold Life restart, retaining the exact transcript, workspace, child identity, and unresolved native approvals. Numbered write-ahead inputs preserve exact prompt, Stop, setting, and permission-reply bytes. An accepted command and a complete pipe-delivery receipt are separate evidence; neither proves that the provider parsed or applied the command. Native replies supply that evidence separately. Uncertain delivery remains protected, and unsupported, corrupt, foreign, or missing ownership cannot authorize replacement work or another approval answer. Restored queues remain paused; prompts and approvals are not automatically replayed.

The implementation's version gates recognize the recorded Codex `0.162.1` and Claude Code `2.1.278` contracts. Recovery reconstructs committed output and parser progress before publication and preserves root/child ownership under an exclusive writer lease. Studio records planner preparation, staging-workspace ownership, and separate source/settings/reload receipts. A started action is observed and reconciled rather than executed again; a completed source action remains completed if later history bookkeeping fails. Historical source receipts remain bound to their recorded snapshots, and scheduling a reload alone does not establish that the applied revision appeared in a fresh native document.

This section remains conditional on the final integrated native matrix. The current isolated Linux Electron/SSH Codex streaming-restart case passed, while Claude approval recovery remains unresolved (`PENDING_CLAUDE_APPROVAL_RECOVERY`). These observations do not certify final Local/SSH and Codex/Claude coverage or establish Windows native recovery. See [native active-session recovery](native-active-recovery.md) for the recorded implementation and contract limits.
