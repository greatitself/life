# Life 0.7.0

Life 0.7 separates coding, Research, and application customization while improving running conversations and SSH continuity. It incorporates all 10 new October 9 backup extensions, bringing the built-in catalog to 37 extensions.

- **Visible project and environment:** The new-thread page identifies the active project. The header's Current Active Environment shows the machine, folder, connection state, scope, and installed providers.
- **Independent Research:** Goals, maps, artifacts, and conversations use the connected machine's `~/.life/research`, without selecting an Agents project. Goal overviews and individual problems have separate working directories with native instructions and structured context. Research conversations stay out of Agents project lists. Recognized legacy `.research` content is copied with original data retained and conflicts preserved; linked conversations keep their provider IDs when their working directories move.
- **Research methodology:** Anti-abstraction decomposes a whole into parts; abstraction composes parts into a whole. Twelve approaches connect requirements, assumptions, evidence, candidates, interactions, inquiries, and verification. Grounding remains a separate evidence step. Native method-guide/schema files and immutable per-invocation records provide context without changing the user's prompt.
- **Life Studio:** A dedicated entry at the bottom of the left sidebar provides separate customization conversations and Details, Changes, Build, and Recovery controls. Valid proposals can apply automatically or wait for review. Ordinary chat no longer applies `/life` customizations.
- **Exact user messages:** Normal messages, queued follow-ups, steering, and Studio continuations preserve the submitted text. Research and Studio context uses separate native instruction and data files rather than appended prompt instructions. Selected attachments use native content or visible file paths.
- **Provider-generated titles:** Codex and Claude titles come from provider metadata or an isolated metadata task, without adding title instructions to the coding conversation or using first-message excerpts as a fallback.
- **Readable conversations:** Responses, reasoning, tool output, approvals, and subagent activity keep their order and identity. Full retained output remains available through raw views, copying, and downloads alongside bounded previews.
- **Steering and reliable queues:** Normal follow-ups wait for provider-confirmed completion. The Steer control and queued steering arrow steer the running turn without interrupting it. Failures, approvals, interruption, or disconnection do not automatically release queued messages.
- **Settings while working:** Model, reasoning, and speed controls stay usable during a response. Supported Codex versions apply changes at the next model step; older versions save them for the next turn. Claude model/effort changes apply at subsequent model requests, and Fast mode changes on the next turn, without stopping or resending prompts.
- **Built-in feature controls:** Enable, disable, delete, and restore incorporated features individually. Choices persist without recompiling historical backup snapshots, while saved chats, Research data, and recovery controls remain intact.
- **SSH interruption recovery:** A detached Node.js or Python 3 broker keeps the remote provider running through an unexpected SSH loss. Life reconnects and catches up from its private output journal without replaying the prompt. Credentials used for automatic retry stay in memory.
- **Stability fixes:** Automatic reconnection restores the active project before announcing a ready connection, avoiding competing folder selections and a blocking project picker. Empty dropdown reset values cannot crash the renderer. Large Research maps and conversation diffs use bounded rendering, and native recovery can stop a blocked custom map.
- **Host chat history:** Browse and preview Codex and Claude Code sessions created outside Life, search and paginate them, then continue with their original session IDs. Browsing and importing leave original provider records unchanged.

The October 9 incorporation includes compact attachments and source receipts, project colors, goal/problem maps, header layout refinements, Claude's terracotta mark, persistent Research maps and drafts, filters, and the built-in feature manager. Exact old extension bundles remain exportable archives; edited or unrelated custom extensions are preserved for adaptation.

Windows retains Life's installation identity and data directory. CI checks upgrades from 0.1.0, 0.5.1, and 0.6.0 against the new installer. Use Updates or run the new installer over the existing installation. Windows and Linux AppImage support in-app updates; unsigned macOS and Debian installations use the latest installer. Signing remains deferred, so platform trust warnings may still appear.

Provider availability follows the installed CLI, account, and policy. SSH continuity covers transport interruption while Life is running; it does not promise automatic continuation after remote reboot, provider termination, or full application shutdown. Native Electron changes still require a packaged update.

Validation: 1,175 automated tests pass, alongside 79 browser regression groups for live settings, duplicate steering, Studio child lifecycles, queues, conversation presentation, and renderer recovery. Research methodology passes 34 Chromium checks. Release checks exercise source and packaged Electron, all nine packaged customization compiler checks, and Windows upgrades from 0.1.0, 0.5.1, and 0.6.0.
