# Life 0.11.1

Life 0.11.1 keeps compatible source customizations usable after updates, shows remaining provider account allowance prominently, and improves Windows installation. It includes the desktop Research workspace, provider update notices, and responsiveness improvements from the previous releases.

- **Compatible customizations survive updates automatically.** A change to the installed source fingerprint previously disabled every saved customization, even when only the application version changed. Life now rebuilds compatible enabled layers against the installed source and activates a new revision only after successful compilation. Untouched files receive current Life code; user edits, extension ordering, dependencies, and original exportable bundles remain preserved.
- **Recovery remains protective.** Explicitly disabled and crash-recovered customizations stay disabled. Conflicting edits, unavailable historical preimages, and compiler failures preserve the source revisions and use the installed interface with a specific diagnosis. The migration does not bypass fingerprint checks or run an old compiled bundle against new native contracts.
- **Usage means allowance left.** Usage leads with provider-reported remaining account allowance and reset times for Codex and Claude Code. Retained-session token and cost statistics remain separate. Values are scoped to the connected machine and provider account, and stale balances are cleared when the account changes. Available credit balances use the provider's currency; unavailable quotas remain unavailable rather than being inferred from conversation tokens.
- **Providers can initialize together.** Opening a Codex transport no longer cancels Claude model discovery or a queued Claude turn on the same connected machine. Machine and workspace changes still cancel obsolete operations.
- **Windows deployment avoids redundant copying.** When the installation folder is confirmed empty and supports direct extraction, the installer writes the payload there once and verifies every packaged file against trusted SHA256 hashes. Other supported folders retain the staged copy and retry path, with verification before copying and before registration or launch. Unrelated existing files remain preserved, and unsafe or unreadable installation paths stop before writing.
- **Complete verification uses Windows cryptography.** The installer hashes every packaged file through Windows CNG with bounded reads and checked cleanup. Unsupported cryptographic setup retains the complete stock hash path; unreadable files, changed contents, and verification failures stop installation.
- **Process checks avoid repeated startup work.** A single complete process query can confirm that no running application is in the installation scope. Running applications, incomplete queries, restricted policy, and unexpected results retain the complete existing checks. The previous version's uninstaller remains unchanged.
- **Measured upgrades with preservation checks.** Release verification checks only **0.11.0 → 0.11.1** and reports the complete installer process time. Installation identity, saved-data preservation, synchronous cleanup, bundled compiler verification, and installer metadata remain required checks. Publication uses these correctness checks without a fixed upgrade-time threshold.
- **The responsive desktop remains fully bundled.** Dependencies remain in Electron's archive, and Studio prepares its verified compiler cache only when needed. Streaming output, thread navigation, deferred dialogs, and map movement retain the rendering improvements from 0.11.0. Supported updates keep background download and verification, differential downloads, the installer cache, and an explicit restart choice.

## Verification

The benchmark appended to the published release notes reports that release's observed installer-process time, installer hashes, installed file counts, and saved-data preservation checks. Timing covers installer launch through exit, including the previous version's uninstaller and synchronous installer cleanup; no time is subtracted. Downloads and external verification are recorded separately. One runner sample does not establish a speed guarantee on every computer, and later operations may benefit from warm operating-system caches. Customization rebuilding occurs on application startup and is checked separately from the installer-process timer.

Source tests exercise successful migration, preservation, idempotent restart, disabled layers, crash recovery, conflicts, and failed compilation. Packaged runtime checks use the actual bundled Electron executable, npm, and native compiler. Provider quota checks use native protocol responses and read-only account queries; paid inference is not part of the release verification. Windows native checks cover process policy, unsafe paths, payload corruption, protected metadata, genuine extraction interruption, repair, and preservation of user data.

Windows x64, Linux x64, and both macOS architectures remain supported. Existing data directories remain preserved; installer signing is unchanged. All release assets are assembled from one verified source commit.
