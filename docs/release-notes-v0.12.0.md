# Life 0.12.0

Life 0.12.0 makes the Agents workspace easier to organize and return to: pinned threads keep their place, parked work resurfaces when it needs attention, drafts retain their files, and completed responses keep their activity available to inspect.

- **Keep important threads in order.** Pin and unpin threads, then use **Move up** and **Move down** to arrange pinned or active work. **Arranged** sorting keeps their manual order stable while responses stream and titles or Git observations update. New installations use an ungrouped, manually ordered rail; existing custom sorting, filtering, and grouping preferences remain preserved.
- **Park work without losing it.** Settled, snoozed, and archived conversations have compact expandable sections. Snoozed work wakes at the selected time or when a new request, completion, or failure needs attention. Archive retains history and supports restoration. Pending requests prevent settling or snoozing; running parents, live children, pending requests, and unpaused queues prevent archiving or deletion.
- **See what needs attention.** Unread completion indicators, waiting requests, and failure states are distinct. Opening a thread marks it read, with explicit **Mark unread** and **Mark read** actions. Streaming, title changes, Git refreshes, and old imported history do not create false unread completions.
- **Use the same thread controls everywhere.** Sidebar and conversation-header menus provide pinning, arrangement, rename, read status, export, copy, archive, restore, and deletion controls. Arrangement changes offer **Undo** while preserving newer messages and live provider state. A manual rename cannot be overwritten by a late generated title.
- **Return to the draft you left.** Text and attachment references persist per composer, and saved file bytes restore after restart. Missing files stay visible with a reattach/remove instruction. **New thread** preserves unsent text and files as a separate **Draft thread** and inherits the selected thread's run settings. Preparing or sending a message preserves newer edits; failed sends recover the original text and files alongside them.
- **Read the result and inspect the work.** Successful completed responses keep the final reply visible, with chronological reasoning, tools, approvals, and child activity available in expandable work disclosures. Unresolved requests, live child work, failures, interruptions, and unknown outcomes stay explicit. Successful reported file edits show paths, available line counts, and bounded diff previews, with the original output retained.

The implementation follows inspected feature patterns in [T3 Code at commit f92afe79](https://github.com/pingdotgg/t3code/tree/f92afe79c921dd7de20204e83d62fed0491b4e54), including its [thread action menu](https://github.com/pingdotgg/t3code/blob/f92afe79c921dd7de20204e83d62fed0491b4e54/apps/web/src/hooks/useThreadActionMenu.ts) and [composer draft lifecycle](https://github.com/pingdotgg/t3code/blob/f92afe79c921dd7de20204e83d62fed0491b4e54/apps/web/src/hooks/useHandleNewThread.ts). Life implements these behaviors in its existing Electron, SSH, Codex, and Claude architecture with original code. See [conversations and Research](conversations-and-research.md) for the controls and recovery behavior.

## Verification

Thread verification covers arrangement and attention state, guarded destructive actions, title races, attachment restoration, asynchronous draft preservation, and chronological completed activity. Browser interaction checks exercise the actual Agents interface; native desktop checks retain provider, project, queue, Research, customization, and restart coverage. Controlled provider fixtures validate behavior without paid inference.

Windows upgrade verification checks only the latest published predecessor, **0.11.1 → 0.12.0**. It retains installation identity, saved-data hashes, payload integrity, native process checks, genuine interrupted-install recovery, bundled compiler/customization checks, and synchronous cleanup. The published benchmark reports the complete installer launch-through-exit time, including the previous version's uninstaller; no time is subtracted. Timing is informational, and one runner sample does not guarantee an installation or upgrade duration on another computer. Customization rebuilding is checked separately on application startup.

The desktop release pipeline builds Windows x64, Linux x64, and both macOS architectures from one verified source commit, checks update metadata and checksums, and preserves existing data directories. Installer signing remains unchanged.
