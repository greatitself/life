# Life 0.10.0 frontier alignment

Reviewed **October 10, 2026**. This release aligns Life's Electron harness with current provider protocols and selected T3 Code interaction patterns. Its claims concern implemented behavior and verified protocol surfaces; they do not imply complete feature parity.

## Upstream baseline

T3 Code was inspected at **v0.0.45**, commit [`0be20c86c2962b7b581dfc79df9ab34b4fbdab14`](https://github.com/pingdotgg/t3code/tree/0be20c86c2962b7b581dfc79df9ab34b4fbdab14), committed October 10. Relevant references are its [active-turn queue capability checks](https://github.com/pingdotgg/t3code/blob/0be20c86c2962b7b581dfc79df9ab34b4fbdab14/packages/client-runtime/src/state/threadWorkflows.ts), [stable thread projections](https://github.com/pingdotgg/t3code/blob/0be20c86c2962b7b581dfc79df9ab34b4fbdab14/packages/client-runtime/src/state/threadDetail.ts), [periodic latest-snapshot persistence](https://github.com/pingdotgg/t3code/blob/0be20c86c2962b7b581dfc79df9ab34b4fbdab14/packages/client-runtime/src/state/cachePersistence.ts), and [remembered scroll anchors](https://github.com/pingdotgg/t3code/blob/0be20c86c2962b7b581dfc79df9ab34b4fbdab14/apps/web/src/components/chat/timelineScrollAnchoring.ts).

Separate promptless probes exercised upstream CLI binaries:

- **Codex 0.162.1:** app-server initialization with experimental API enabled succeeded; `account/rateLimits/read` was probed. Its generated experimental protocol was byte-identical to installed 0.162.0. Reference: [official app-server protocol](https://learn.chatgpt.com/docs/app-server).
- **Claude Code 2.1.296:** stream-JSON `initialize` and `get_usage` controls used `skip_behaviors: true`. Initialization advertised models including Opus, Sonnet, and Haiku 5.5; effort levels were reported dynamically, and fast mode support appeared only for default/Opus choices. Clearing/changing effort, clearing/enabling fast mode, selecting the default model, and interrupting received acknowledgements. Switching to bypass permissions without the launch flag was rejected. References: [programmatic execution](https://code.claude.com/docs/en/headless), [permissions](https://code.claude.com/docs/en/permissions), and [fast mode](https://code.claude.com/docs/en/fast-mode).

These probes invoked no inference, purchased no model turns, and left globally installed versions unchanged. Local records are `/tmp/life-codex-0.162.1-handshake-proof.json`, `/tmp/life-codex-protocol-0.162.1`, and `/tmp/life-claude-2.1.296-protocol-proof.json`.

## Implemented behavior

| Area                  | Life 0.10.0 behavior                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native conversations  | Codex uses app-server; Claude uses a persistent bidirectional stream-JSON process. Exact prompts, provider IDs, and project/Research scope survive follow-ups. Background Claude child events remain associated with their parent after the root becomes idle.                                                                                                                                                                                       |
| Models and controls   | Native model capabilities drive effort, fast mode, and supported image input. Unsupported combinations produce actionable errors. Acknowledged configuration distinguishes live changes from changes applied at the next native request.                                                                                                                                                                                                             |
| Provider requests     | Permission requests, native questions, supported primitive MCP forms, and URL elicitation receive distinct controls. Multiple choices, custom answers, optional fields, and secret inputs retain their meaning. Secret answer values are redacted from saved history. Provider cancellation/resolution removes stale controls without ending the turn.                                                                                               |
| Turn lifecycle        | Steering targets the running native turn; automatic queued follow-ups require actual completion. Stops settle message/tool state. Retryable failures remain visible without falsely failing the turn. Independent child requests remain replyable. Distinct native child runs reopen activity; stale lifecycle replays cannot revive an old run or rewrite its completed output.                                                                     |
| Usage                 | The dashboard filters saved sessions by machine/provider and shows reported tokens, estimated costs, account windows, and available context data. Cumulative snapshots are deduplicated; cache and reasoning subsets are not added twice. Claude per-turn main-loop usage is kept separate from cumulative model/cost totals. Missing prices remain unreported. See [official cost scopes](https://code.claude.com/docs/en/agent-sdk/cost-tracking). |
| Provider updates      | Connected-machine versions are compared with published npm releases. Checks cache results, show stale/unavailable states, refresh installed versions, and link official installation/update instructions. They do not silently replace provider installations.                                                                                                                                                                                       |
| Streaming and history | Token bursts batch at 16 ms; actionable events flush in order. Native history uses serialized atomic disk checkpoints, a 600 ms quiet save, and a two-second maximum streaming checkpoint. Close/reload flush pending events and history. Storage failures preserve existing data.                                                                                                                                                                   |
| Timeline              | Unchanged turns reuse their props; timer ticks avoid transcript rerenders. Per-surface/thread scroll positions retain visible message offsets, including late image/layout changes. Sending or selecting “latest” resumes following. Native message-navigation anchors remain available.                                                                                                                                                             |

Implementation is in [agents](../src/main/agents.ts), [request normalization](../src/main/codex-requests.ts), [usage](../src/renderer/usage.ts), [provider updates](../src/main/provider-updates.ts), [event batching](../src/renderer/agent-event-batch.ts), [persistence](../src/renderer/conversation-persistence.ts), and [scrolling](../src/renderer/conversation-scroll.ts).

## Verification and limits

Regression coverage includes protocol/request validation, background child lifecycle, resumed-session usage, update races, ordered event batching, checkpoint recovery, and secret-answer redaction. Browser checks exercise actual renderer controls, large outputs, approval retries, and seven scroll scenarios. Run `npm test` and the smoke commands in [CI](../.github/workflows/ci.yml). Packaged Electron checks use fake provider CLIs over actual SSH; they are distinct from the upstream promptless probes. Release workflows verify source identity, updater metadata, and the Windows upgrade from the latest preceding release (0.9.0 for 0.10.0).

Life remains a desktop SSH product supporting Codex and Claude. It does not reproduce T3's additional providers, mobile/relay clients, or full orchestration system. Its timeline is not fully virtualized, and arbitrary MCP schemas/UI surfaces are not universally supported. Model access, account limits, costs, and feature availability remain provider-reported; probes establish protocol compatibility, not paid-inference quality or every hosted-account configuration.
